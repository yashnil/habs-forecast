### Things to know before reading the rows

1. **The v2 map UI is dead code in v4.** `components/LiveOceanMap.tsx`, `map/LayerDock.tsx`, `map/Inspector.tsx`, `port/PortPanel.tsx`, `map/PlaceChip.tsx` and `map/NavCard.tsx` still exist, but nothing imports `LiveOceanMap` (grep finds no importer). So any behaviour that only lived in them is gone for users, even though the code is still there. Examples: the multi-sensor coverage, agreement and VIIRS-age lines (`LayerDock.tsx:524,658-671`), the knots conversion, and the 24 h mean "tidal" note.
2. **`/` is now `v4/explore/Explore.tsx`.** It mounts `MapCanvas` with `chrome="none"` (`Explore.tsx:493`) and `fade={false}` (`:504`). That turns off the v2 county control, the map's attribution control and the `map-field-loading` words (`MapCanvas.tsx:449-451,782`), and makes every raster cut instead of fade.
3. **The v2 `inspect=lat,lon` deep link changed.** It now decodes to a **point** selection (`v4/state/selection.ts:56-57`). The point view shows only coordinates, nearest stations and a "What C-HARM publishes for this cell" button (`Inspect.tsx:380-410`). It shows **no C-HARM, currents or satellite values and no notices**. The v4 README says v2 `inspect` links "open the same view", but they don't. `explore.spec.ts:62` has "inspect" in its title but never passes `inspect=`.
4. **Values for currents and satellite pixels appear only in the hover readout.** That's the desktop fine-pointer hover only (`Explore.tsx:348,505`; `lib/readout.ts:74-111`). A click opens the point view, which has none of those values. Keyboard, touch and screen-reader users have no way to reach them, even though the comment at `HoverReadout.tsx:16-18` says the inspector is "the keyboard and screen-reader route to the same values".
5. **Explore has no freshness note for the forecast.** The only freshness signals are:
   - the layer-list line "Run of Oct 8 · 4 days ago" (`LayerPanel.tsx:22-26`);
   - the stamp's relative day (`lib/stamp.ts:72-77`);
   - the status centre's `model` source (`Explore.tsx:318-329`).

   The status centre maps only `stale` to "stale". A **historical** run (two weeks old) is reported as `ready`, and nothing says "does not describe current conditions".
6. **The Explore notices panel is thinner than the drawer it replaced** (`v4/shell/Notices.tsx:48-107`):
   - It has no agency text, no per-record flags and no expected-end-passed warning (`lib/official.ts:111-112`).
   - It doesn't show the review or last-check age, has no `tel:` links, and doesn't say "does not mean an area is open".

   The briefing's notice list (`v4/coast/Briefing.tsx:345-370`) has the same gaps. The full v2 drawer (`components/shell/OfficialShell.tsx`, `components/official/Official.tsx`) survives only on the AppShell pages (`/sources`, `/bloom`, `/fisheries`, `/about`).
7. **County lines still draw, but the control is gone.** `CountyLayers` is always mounted (`MapCanvas.tsx:453`) and reads the v2 preference `cw-counties-v1` from localStorage (`components/map/Counties.tsx:11-35`), but `CountyControl` is not mounted in v4 (`MapCanvas.tsx:451`). **Anyone who turned county lines off in v2 cannot turn them back on in v4**, and the "do not define fishery closures" note is no longer shown.
8. **The URL now always pins the layer.** `writeUrl` writes `layer=` as soon as a choice exists (`Explore.tsx:146-160`). v2 deliberately left the layer out of the URL when it was chosen by the opening policy.
9. **The layer list claims to be a radio group but has no arrow keys.** It is a `role="radiogroup"` with no arrow-key handler (`LayerPanel.tsx:60-93`). Compare the Timebar, which has one (`Timebar.tsx:93-100`).

Helpers that the proposed tests below rely on (all exist in V4):
- `OK`, `FAILED`, `NODATA`, `M2` from `tests/e2e/ports.ts`.
- `open()` as in `explore.spec.ts:13-18` (`page.clock.setFixedTime`, wait for `notices-button` and `__cwMap.loaded()`).
- The pointer-hover helper from `coastline.spec.ts:20-28`.
- Fixture JSON from `tests/fixture-data/v1` (served from `public/data/fixture/v1`).
- Fixture times: run issued 2026-10-08 (leads valid Oct 7 to Oct 10); newest currents hour `hfr2km_currents_20261008T12Z`, so timebar testids are `time-20261008T12Z` and `time-mean`.

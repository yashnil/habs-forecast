## (2) The OLCI "404 on the time listing" — diagnosis and fix

What the pipeline sends (`pipeline/coastwatch_pipeline/sources/satellite.py`, `times_url`): `https://coastwatch.noaa.gov/erddap/griddap/{ds}.csv0?time[(START T00:00:00Z):1:(last)]` with START = run date − 7 d, then `no_matching_results()` accepts a 404 only when the body says "Your query produced no matching results".

Reproduced today:

| dataset | start | HTTP | body |
|---|---|---|---|
| noaacwS3AOLCIchlaSectorCIDaily | 2026-10-08 | 200 | 8 times, last 2026-10-14T18:44:40Z |
| noaacwS3AOLCIchlaSectorDIDaily | 2026-10-08 | 200 | 8 times, last 2026-10-14T17:54:10Z |
| noaacwS3BOLCIchlaSectorCIDaily | 2026-10-08 | **404** | **generic HTML "404 \| NOAA CoastWatch" page** (`Server: Apache`, `Via: 1.1 coastwatch.star.nesdis.noaa.gov`, `Content-Type: text/html`) |
| noaacwS3BOLCIchlaSectorDIDaily | 2026-10-08 | **404** | same HTML page |
| noaacwS3BOLCIchlaSectorCIDaily | 2026-09-20 | 200 | 2026-09-17, 09-22, 09-23, 09-30, **2026-10-01T19:32:23Z** (last) |
| noaacwS3AOLCIchlaSectorCIDaily | 2026-10-16 (future) | **404** | same HTML page |

So: (a) the dataset ids have **not** changed (`.das`, `.csv?time`, `.csvp?time`, `.json?time[(last)]`, `.csv0?time` all 200 for S3A CI/DI, and `noaacwS3AOLCIchlaSectorCIDaily` is still the right sector for everything west of 120° W, 29.8–45.2 N; DI east of 120° W covers San Diego/LA); (b) **Sentinel-3B's NOAA feed is stalled** (CI last 2026-10-01, DI last 2026-10-03), so a 7-day window legitimately matches nothing; (c) **coastwatch.noaa.gov's Apache front end replaces ERDDAP's 404 error text with a site-wide HTML 404 page**, so `no_matching_results()` cannot see "no matching results", returns False, and the fetch is raised as an outage.

Fix (small, in `satellite.py`): make the "nothing newer" decision independent of the error body. Either
- probe first: `GET {server}/griddap/{ds}.csv0?time[(last)]` (always 200 while the dataset exists; a 404 whose HTML mentions "unknown datasetID" or a non-200 `.das` means the dataset is really gone), parse the single timestamp, and only call `times_url()` when `last >= start`; or
- keep the current call and, on a 404 with `Content-Type: text/html` (or the string "404 | NOAA CoastWatch"), confirm the dataset with `{ds}.das` (200 → treat as "no newer scene", 404 → outage).
Also log S3B's staleness as a health note ("S3B last scene 14 days old") rather than failing the run; S3A alone is current. If true S3B redundancy matters, the Copernicus Marine `cmems_obs-oc_glo_bgc-plankton_nrt_l3-olci-300m_P1D` dataset (S3A+S3B merged) is the alternative, but it needs an account and attribution (see (3)).

## (3) Must NOT be used, or only under conditions

- **SCCOOS/UCLA-JPL ROMS** (`roms_ncst`/`roms_fcst`, west.rssoffice.com): dead since 2022-12 / host unreachable — do not list as a source.
- **UCSC CCSNRT / WCOFS-Monterey 150 m nest**: UCSC terms say "prototype … NOT INTENDED TO BE USED FOR NAVIGATIONAL, LIFE SAFETY, OPERATIONAL OR RELATED PURPOSES"; CC BY 3.0 requires attribution; the 150 m nest is 8 months stale. Not for a fishermen-facing conditions panel.
- **Copernicus Marine (I2, J) and EUMETSAT**: no anonymous access; a personal login that must not be shared/embedded in a public pipeline without the account owner's decision; mandatory credit "Generated using E.U. Copernicus Marine Service Information" (+DOI) visible on the access page, and usage records kept. Anonymous scraping of NRT files is not allowed.
- **Gap-filled products (NOAA DINEOF 2/9 km, GlobColour gap-free 4 km)**: may be shown only as "reconstructed/interpolated"; never as an observation and never as a harbor value (2–9 km cells; 9 km NRT is EXPERIMENTAL; 2 km lags 18 days).
- **IFCB auto-class scores**: no licence statement on ifcb.caloos.org, `has_class_scores:false` on the API while legacy CSVs exist — provisional CNN output. Do not present as Pseudo-nitzschia counts or as validated HAB detection; ask the dataset contacts before redistribution.
- **CDFW status**: no structured feed; the HTML status table and news releases may be read but, per project rules, never auto-marked verified/lifted/expired — a person runs `cwp review-official`. The RAMP zone polygons (ds3120) are fine to use as geometry.
- **api.weather.gov** requires a descriptive `User-Agent`; **PZZ750** does not exist (San Diego coastal zone is **PZZ740**).
- **NDBC/CDIP/CO-OPS**: public domain / unrestricted, but keep polling modest (CO-OPS: 6-min data ≤ 31 days per request; NDBC realtime2 files update at most hourly; CDIP realtime files every 30 min) and credit CDIP/USACE as requested.
